### [Qwen 3.8 follows GPT-5.5 Pro reasoning prefills](https://gist.github.com/wsxiaoys/e0286dc6bb624ff5fdf49e7f4c528ba3) ⭐️ 8.0/10

A Hacker News discussion highlights a novel technique to investigate potential model distillation or shared training data between large language models, specifically comparing Qwen 3.8&\#x27;s reasoning prefills with recovered Chain of Thought \(CoT\) from GPT-5.5 Pro. This method involves using a benchmark to generate CoT from a state-of-the-art model, then feeding the initial portion of that CoT as a prefill to an open-source model like Qwen 3.8 to observe similarities. The findings raise significant questions regarding AI development practices, intellectual property, and the integrity of open-source initiatives.

hackernews · wsxiaoys · Sep 9, 17:24 · [Discussion](https://news.ycombinator.com/item?id=49630026)

**「Background」** Chain of Thought \(CoT\) is a technique where large language models \(LLMs\) generate a series of intermediate reasoning steps before arriving at a final answer, which can improve their performance on complex tasks. While some LLM providers conceal these step-by-step reasoning traces to protect intellectual property, the &quot;Stolen Thoughts&quot; paper describes a method to recover these encrypted CoT blocks from proprietary APIs, revealing the models&\#x27; internal reasoning processes.

**「Impact」** If substantiated, the observed reasoning prefill overlaps between Qwen 3.8 and GPT-5.5 Pro raise significant intellectual property concerns for AI developers and organizations, potentially undermining the substantial R&amp;D investments required to build advanced AI models.

**「Community Discussion」** Community members clarified that the technique involves recovering Chain of Thought \(CoT\) from advanced models and using it as a prefill for open-source models, referencing a paper on &quot;stolen thoughts.&quot; Concerns were raised that Qwen 3.8&\#x27;s training date post-dated the paper&\#x27;s release, suggesting it might have been exposed to those specific CoT examples, while another user proposed that shared training data on benchmark solutions could explain overlaps rather than distillation. Additionally, the generalizability of using recovered CoT for improving local model performance was questioned.

### [GNU Radio Comes to Web Browsers via WebAssembly and WebUSB](https://gnuradioworld.com/) ⭐️ 8.0/10

The powerful GNU Radio software-defined radio \(SDR\) framework has been successfully ported to web browsers, leveraging WebAssembly for complex signal processing and WebUSB for direct hardware interaction. This development significantly enhances the accessibility of advanced signal processing tools, allowing users to run sophisticated SDR applications directly in a browser without local installations. It also demonstrates the web&\#x27;s growing capability to host complex applications and control hardware, pushing the boundaries of what is possible with web technologies.

hackernews · kristianpaul · Sep 9, 15:53 · [Discussion](https://news.ycombinator.com/item?id=49628576)

**「Background」** GNU Radio is a free and open-source software development toolkit that provides signal processing blocks for implementing software-defined radios, usable with or without external RF hardware. WebAssembly is a low-level bytecode format designed to run high-performance applications client-side in web browsers, offering near-native performance. WebUSB is a JavaScript API that enables web applications to securely access and interact with USB devices directly from the browser, primarily supported by Chromium-based browsers.

**「Impact」** The porting of GNU Radio to web browsers via WebAssembly and WebUSB significantly enhances the accessibility of advanced software-defined radio \(SDR\) and signal processing, allowing users to interact with USB hardware directly from a web application.

**「Community Discussion」** Community members expressed excitement, with some comparing the project to MaxMSP and planning to explore it further, while others shared their own WebUSB/WASM projects for RF scanning and decoding. However, some feedback indicated that the current demo might not be clear enough for newcomers, raising questions about its introductory effectiveness and expected functionality.
