### [酷 URI 永不改变 \(1998\)](https://www.w3.org/Provider/Style/URI) ⭐️ 8.0/10

这篇 1998 年的经典 W3C 文章《酷 URI 永不改变》强调了稳定 URI 对于网络资源持久性和可靠性的重要性。文章指出，URI 应保持不变，以确保信息的可访问性。这一原则在现代网络开发和信息架构中仍然具有高度相关性，是构建健壮网络体验的基础。

hackernews · Klaster\_1 · 8月9日 14:32 · [社区讨论](https://news.ycombinator.com/item?id=49231809)

**「背景」** “Cool URIs Don&\#x27;t Change”是蒂姆·伯纳斯-李于 1998 年撰写的一篇经典 W3C 文章，强调了统一资源标识符（URI）的持久性和稳定性对于网络资源长期可用性的重要性。该文指出，URI 的改变通常是人为决策而非技术限制所致，并提供了设计经久耐用的 URI 的实用建议，例如避免在 URI 中包含日期、作者或文件扩展名等易变信息，以确保网络内容的可访问性和可靠性。

**「影响」** 尽管现代网络开发通过 301/302 重定向和内容管理系统（如 WordPress）的内置功能来缓解 URI 变更问题，但网站的疏忽、移除、重组或下线仍会导致链接失效，影响用户对信息的持续访问。

**「社区讨论」** 社区普遍认为这篇文章是经典之作，其自身 URI 在 28 年间保持不变，进一步证明了其主张的可靠性。然而，评论者也指出，即使是微软（Windows 10）和美国国家科学基金会等机构，其旧链接也可能失效或指向通用页面，新闻网站也常更改 URL。这表明，尽管有缓解措施，URI 的持久性仍是一个持续的挑战。

### [GitHub Models 服务已退役，影响 AI 驱动工作流](https://simonwillison.net/2026/Aug/9/github-models-is-now-retired/#atom-everything) ⭐️ 8.0/10

GitHub 已于 2026 年 7 月 30 日退役其 Models 服务，该服务曾提供一个统一的 LLM 提供商 API 和模型游乐场工具，并允许 GitHub Actions 中的代码利用现有 GitHub API 密钥执行提示。这一退役对依赖其进行 AI 驱动工作流的开发者造成影响，例如作者的 GitHub Actions 运行因服务不可用而失败。尽管 GitHub 未说明具体原因，但推测可能与编码代理模式导致免费或补贴代币成本过高有关。开发者现在需要寻找替代方案，例如作者已成功切换到带有月度消费限制的 OpenAI API 密钥，并使用 GPT-5.6 Luna 来生成内容摘要。

rss · Simon Willison · 8月9日 22:48

**「背景」** GitHub Models 是一项服务，它为大型语言模型（LLM）提供商提供统一的 API 接口和一个模型游乐场。其主要优势在于，运行在 GitHub Actions 中的代码可以直接利用 GitHub 环境中已有的 API 密钥来执行 LLM 提示。这项服务旨在支持 GitHub Next 的“持续 AI”（Continuous AI）概念，即在开发工作流中无缝集成 AI 功能，例如通过 GitHub Actions 构建、测试和部署 AI 驱动的项目。

**「影响」** 依赖 GitHub Models 服务在 GitHub Actions 中执行 AI 驱动工作流的开发者现在必须迁移到其他 LLM 提供商或直接 API 集成，以维持其自动化流程。
