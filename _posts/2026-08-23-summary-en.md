The malware does not affect Android Auto, which operates as a screen mirroring protocol, nor can it self-propagate to all Android-based head units. This highlights a growing security concern within the expanding category of connected embedded systems in vehicles.

hackernews · campuscodi · Aug 23, 13:05 · [Discussion](https://news.ycombinator.com/item?id=49408550)

**「Background」** Android-based automotive head units are in-car infotainment systems that run the Android operating system, often installed as aftermarket upgrades. These units can connect to a vehicle&\#x27;s Controller Area Network \(CAN\) bus, which is a communication system allowing various electronic control units \(ECUs\) within the car to interact. This connection means that a compromised head unit could potentially access or interfere with critical vehicle systems, such as body control modules \(BCMs\) or even driving controls, as demonstrated by past research into vehicle vulnerabilities.

**「Impact」** This vulnerability allows malware to potentially control vehicle functions through the CAN bus, leading to risks like system crashes or unauthorized access to vehicle controls. While currently limited to specific aftermarket units, the vector demonstrates a critical security flaw in the automotive supply chain.

**「Community Discussion」** Community members clarified that the malware primarily targets cheap Chinese aftermarket Android head units via their official OTA updates, distinguishing it from Android Auto or all Android-based systems. Concerns were raised about the potential for malware to propagate laterally from paired phones and, more critically, to directly cause vehicle system interference or crashes due to head unit connections to the CAN bus.

### [ShardFlow Achieves 28 TPS on Qwen2.5-7B Across Cloud Regions with Speculative Decoding and CUDA Graphs](https://www.reddit.com/r/MachineLearning/comments/1vw5ysj/28_tps_on_qwen257b_across_two_separate_cloud/) ⭐️ 8.0/10

A new distributed LLM inference framework, ShardFlow, has been developed to split HuggingFace transformers across multiple GPU machines and mitigate Wide Area Network \(WAN\) latency using neural speculative decoding. Benchmarked on two GCP T4 nodes in Iowa and Oregon, communicating via an AWS EC2 TCP relay in Ohio with ~86ms RTT, ShardFlow achieved a peak of 28.10 TPS \(20.31 TPS average\) on Qwen2.5-7B. This performance is significantly higher than the 4.92 TPS non-speculative baseline, largely because speculative decoding transforms WAN latency from a per-token to a per-round cost, committing 4.07 tokens per round trip. Further optimization with CUDA Graphs dramatically reduced draft generation latency from 112ms to 25ms by consolidating ~1500 Python-launched CUDA kernels into a single driver call.

reddit · r/MachineLearning · /u/katua\_bkl · Aug 23, 12:30

**「Background」** Qwen2.5-7B is a large language model from Alibaba, pretrained on up to 18 trillion tokens, offering multilingual support for over 29 languages. Speculative decoding is a technique to accelerate LLM inference by using a smaller, faster model to draft multiple tokens, which a larger, more accurate model then verifies in a single step, significantly reducing the per-token generation time. CUDA Graphs optimize GPU workloads by capturing a sequence of operations \(like kernel launches and memory copies\) and replaying them with minimal CPU overhead, which is particularly beneficial for Python-based deep learning applications.

**「Impact」** This framework provides a substantial performance boost for deploying large language models across geographically separated cloud regions, making distributed LLM inference more practical and efficient over high-latency public internet connections.
